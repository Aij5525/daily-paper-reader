## 摘要
随着人工智能（AI）和大语言模型（LLM）在日常应用中的普及，其自然语言解释能力显著提升。AI的一个新兴应用是与网络管理和编排实践的集成。这种集成的一个实例是LLM增强的意图驱动网络，其中网络运营商将使用自然语言控制网络。本工作展示了在意图驱动的5G+核心网络中，使用带有语义路由器的动态路由来识别网络运营商提示中的意图，并提取实现意图所需的必要细节。此外，通过评估多个编码器的静态路由选择性能，以及针对一系列真实运营商提示的动态路由细节提取准确性，对静态路由选择进行了评估。展示的结果表明，静态和动态路由在细节提取和模式格式化方面均能成功实现。

## Abstract
As the use of Artificial Intelligence (AI) and Large Language Models (LLMs) is becoming common in everyday applications, their ability to interpret natural language has increased significantly. An emerging application of AI is integration with network management and orchestration practices. An instance of this integration is LLM-enhanced intent-based networking, where network operators will control a network using natural language. This work presents the use of dynamic routes with a semantic router to identify an intent from a network operator's prompt and extract necessary details for intent fulfillment in intent-based 5G+ core networks. Furthermore, the performance of static route selection is assessed by evaluating multiple encoders and dynamic route detail extraction accuracy against a series of realistic operator prompts. The presented results show that static and dynamic routes are successful in detail extraction and schema formatting.

### 1. 核心问题与整体含义

- **研究背景**：随着5G+网络、物联网、MEC和网络切片等新技术不断涌现和演进，现代网络在规模和动态性上急剧增长，人工进行网络管理已变得不可持续。业界公认 Zero-touch Network and Service Management（ZSM）为最终目标，即实现自配置、自优化、自修复的完全自治网络。
- **研究动机**：从 Human-in-the-Loop 向 Human-on-the-Loop 过渡是实现 ZSM 的必经阶段。意图驱动网络（IBN）让运营商以自然语言声明目标和需求，由网络自主响应。LLM 强大的自然语言理解能力为该场景提供了独特机遇。
- **核心问题**：如何从运营商的自然语言提示中准确识别意图，并可靠地提取履行该意图所需的细节参数，将其转化为机器可执行的策略模式（schema），同时避免 LLM 常见的幻觉和随机输出问题。
- **整体含义**：本文在意图驱动的5G核心网（5GC）场景下，提出将语义路由器由静态路由升级为动态路由，实现"意图识别 + 参数提取 + 策略格式化"的端到端能力，向完全的零接触网络管理迈进一步。

### 2. 方法论

**（1）核心思想**

采用 Aurelio AI 的 Semantic Router 开源工具。系统由三个子系统组成：用户、路由选择、路由执行。用户发送自然语言消息 → 语义路由器中的编码器计算相似度并选择对应路由 → 被选中的动态路由执行预定义函数，从消息中提取关键参数并格式化为 JSON-like schema 输出，供后续网络履行操作使用。

**（2）意图类型与输入假设**

- 聚焦两类意图：
  - **RNR（Regular Notification Request，定期通知请求）**：提取通知的频率（月/天/时/分/秒）和通知主题（网络元素），如"每35分钟更新密西西比网络的状态"。
  - **IRR（Intent Report Request，意图报告请求）**：提取 UUID 形式的意图标识符（如 I-890234h237），或位置表述（如"最近5个意图"→ [-1,-2,-3,-4,-5]）。
- 系统假设运营商具有系统知识，输入消息中会包含关键信息（如 RNR 必须包含主体+频率，IRR 必须提供意图 ID 或连续的位置表述）；否则触发异常。

**（3）静态路由与动态路由**

- **静态路由**：每个路由定义 40 条 utterances（示例短语）；编码器对用户输入计算相似度，超过该路由阈值即触发。
- **动态路由**：在静态路由基础上挂接预定义函数；函数仅需名称和函数 schema，由 LLM（本文使用 Ollama 上的 Mistral 7B）根据函数 schema 解析用户消息并生成 key-value 输出；无需额外提示词。该机制是本文相较于前作的核心改进——从确定性路由扩展为可提取动态参数的端到端机制。

### 3. 实验设计

- **数据集**：基础提示集为人工编写，再经 Gemini 和 ChatGPT 扩充改写（调整长度、措辞、标点和拼写），形成覆盖 RNR、IRR 和 None（无意图，默认路由）三类提示的综合数据集。每个路由包含 40 条 utterances；动态路由测试使用各 40 条 RNR/IRR 样本。
- **Benchmark / 对比方法**：
  - 五种编码器：Hugging Face（HF）、Alibaba Qwen（AB）、Mistral（MS）、OpenAI（OA）、以及混合编码器 HY（结合稠密+稀疏检索）。
  - 每种编码器分别在训练前和训练后测试，比较准确率和阈值变化。
  - 动态路由测试以 OA 编码器 + Mistral 7B 为基线，评估细节提取的准确性（而非路由选择）。
- **评估指标**：静态路由采用准确率（二元分类问题）；动态路由比较预期输出与实际输出的正确性，包括时间单位归一化转换（如60分钟转为1小时）等规则。

### 6. 主要结论与发现

- **静态路由层面**：OA 编码器整体表现最佳——训练后各意图类别均保持高准确率和低方差（高稳定性），是实时系统中最优选择。HY 混合编码器在 RNR 中略优但稳定性不足；HF 训练后提升显著但波动加大；MS 和 AB 训练后因阈值变得过于严格导致准确率明显下降。
- **None 路由层面**：正确识别无关消息对系统安全至关重要（避免将无效值传给履行函数导致 5GC 误操作）；HF、AB、OA 训练前后均保持高准确率，而 MS 和 HY 训练后虽有改善但波动大。
- **动态路由层面**：使用 OA 编码器 + Mistral 7B，RNR 细节提取准确率为 97.4%（38/39），IRR 准确率为 95%（38/40）；意图 ID 提取成功率达 100%。仅有的错误为时间转换（60 分钟未归一化为 1 小时）和位置参数遗漏/错位，均可通过后处理修正。
- **与前作比较**：前作（GLOBECOM 2024）静态路由最佳编码器准确率为 94%（有限验证集）；本文扩展了验证范围，综合准确率超过 99%，单项准确率可达 100%，同时新增了动态路由的参数提取能力。

### 7. 优点

- **从静态到动态的路由跃迁**：解决了先前架构"只能识别意图、无法提取履行参数"的关键局限，使系统更接近真实可用的端到端意图管理闭环。
- **确定性 + 灵活性的兼顾**：语义路由为系统提供了一层 guardrailing（路由不匹配的用户消息不会触发错误意图），动态路由则赋予了参数提取的灵活性。
- **深度的编码器对比分析**：覆盖 5 种编码器（含混合稀疏+稠密编码器），并对训练前后的阈值变化、准确率及其稳定性做了多维比较，对实际选型有较强的参考价值。
- **开源优先的取向**：使用开源语义路由器工具和开源 LLM（Mistral 7B），避免了前作中对闭源模型的依赖。
- **失败案例的透明分析**：对动态路由中的转换错误和位置参数错误做了具体描述和原因分析，并提出了后处理修正的方向。

### 8. 不足与局限

- **意图覆盖过窄**：仅验证了 RNR 和 IRR 两类相对简单的意图，未涉及部署意图、修改意图、性能保障意图、可行性检查等更复杂的类型。
- **强假设约束**：系统对用户输入格式有明确的先验假设（如 RNR 必须包含频率和主体），在实际运营中，用户表述可能不符合预期格式，鲁棒性有待检验。
- **位置表述限制**：IRR 仅支持连续位置的引用（如"最近 N 个"），不支持任意范围选择。
- **单一 LLM 测试**：动态路由仅评估了 Mistral 7B，未与其他开源/闭源 LLM 做对比；其提取质量可能因模型规模受限。时间转换错误和位置参数错误表明当前模型仍需细化提示词、针对性微调或更强的后处理机制。
- **未实现端到端落地**：本文止步于 schema 输出生成，尚未接入实际的 5GC 履行链路，未在真实网络环境中验证；动态路由测试仅使用 OA 编码器这一种配置作为基线，未探究不同编码器组合下的动态路由效果。
