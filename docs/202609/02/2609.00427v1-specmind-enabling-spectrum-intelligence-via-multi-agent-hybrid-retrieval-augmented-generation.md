## 摘要
无线设备的指数级增长正在推动前所未有的频谱需求，促使频谱管理在空间、时间和设备约束方面做出更细粒度的决策。因此，频谱政策制定者和工程师必须处理来自不同来源的大量数据，这些数据以多种不同形式存在，如文本和表格。这些数据源通常是分散的，需要大量的时间和精力进行整合、搜索和解读。此外，这些信息大多是为人类理解而格式化，不容易被自动化系统直接访问。为了应对这一挑战，我们提出了SpecMind，一种创新的多智能体检索增强生成（RAG）系统，用于在异构数据源上进行推理，实现频谱智能。该系统使自主智能体能够协调专门的子智能体，在政策程序、法律法规和许可数据库之间检索和综合知识。我们开发了SpecBench，一个基于真实许可记录和政策程序的问答（Q&A）数据集，解决了频谱领域RAG系统缺乏评估资源的问题。实验结果表明，SpecMind在频谱相关任务上优于传统的通用RAG系统，在强大的基线上实现了超过80%的胜率。基于智能体的设计实现了更准确的检索、更好的上下文推理以及跨不同类型查询的任务完成度提升。

## Abstract
The exponential growth of wireless devices is driving unprecedented spectrum demand, pushing spectrum management toward more fine-grained decisions across space, time, and device constraints. As a result, spectrum policymakers and engineers must process large volumes of data that come from diverse sources and take many different forms, such as text and tables. These data sources are often disaggregated and require significant time and effort to integrate, search, and interpret. Furthermore, most of this information is formatted for human understanding and is not readily accessible to automated systems. To address this challenge, we propose SpecMind, a novel Multi-Agent Retrieval-Augmented Generation (RAG) system for spectrum intelligence that performs reasoning over heterogeneous data sources. This system enables autonomous agents to coordinate specialized sub-agents that retrieve and synthesize knowledge across policy proceedings, legal regulations, and license databases. We develop SpecBench, a question and answer (Q&A) dataset based on real-world license records and policy proceedings, addressing the lack of evaluation resources for RAG systems in the spectrum domain. Experimental results demonstrate that SpecMind outperforms traditional, general-purpose RAG systems across spectrum-related tasks, achieving over 80% win rate against strong baselines. The agent-based design enables more accurate retrieval, better contextual reasoning, and improved task completion across diverse query types.

### 2.2 数据库构建
论文针对三类异构数据源构建“模态感知”的知识库：
- **法规文本（Regulation Documents）**：使用标准稠密检索，分块为 1000 token、重叠 200 token；先检索 top-20 候选用嵌入相似度检索，再经重排（rerank）取 top-5 上下文。重排采用 Qwen3-Reranker-0.6B。
- **FCC 程序文件（Proceeding Documents）**：采用 GraphRAG 方式建模，抽取实体为节点、关系为边，并做层次化摘要以支持多跳推理；每个程序单独建图以避免跨文档冲突，并支持后续增量扩展。

### 2.3 提示词与代理策略设计
- 提示词被显式设计为代理层级的动作策略：
  - **监督代理提示词**：要求先分解子任务、决定调用子代理还是内部操作，并迭代更新任务状态。
  - **许可代理提示词**：规定先检查数据库 schema，再生成 SQL 查询，并根据返回结果修正；共设计四种 SQL 工具。
  - **程序代理提示词**：先进行程序/主题匹配，再按查询粒度选择 GraphRAG 的 basic、local、global 检索；结构检索失败时回退到 basic retrieval。

## 3. 实验设计

### 3.1 数据集 / Benchmark：SpecBench
- SpecBench 是论文构建的专家级频谱 RAG 问答基准，包含 **450 个 Q&A 对**。
- 覆盖五类问题：
  - Proceeding（31.1%）
  - License（31.1%）
  - Regulation（13.3%，含来自 WiLL 基准的改编例题）
  - Compound（14.4%）
  - Unanswerable（10.0%）
- 根据检索粒度区分：
  - **single-source**（如基于单个证据单元）
  - **multi-source**（基于多个证据单元）
- 考查三种核心 RAG 能力：
  - **噪声鲁棒性**：在检索结果包含噪声时找到正确证据；
  - **信息集成**：跨多个来源综合信息；
  - **负向拒绝**：无足够证据时能够拒答而非幻觉。
- 复合问题进一步区分：
  - **Parallel**：各证据可独立检索，最终合并；
  - **Sequential**：后一步检索依赖前一步中间结果，容易错误传播。

### 3.2 对比方法与设置
- 基线：
  - **Web-search RAG**：用 Google Search 作为检索器，取每个查询 top-20 结果作为生成上下文。
  - **SpectrumRAG**：迭代式 RAG，基于 LLM 查询改写优化检索。
- 评价使用两种骨干 LLM：**Qwen3-8B** 和 **GPT-5.2**；所有方法采用相同的骨干模型；文本嵌入统一使用 `text-embedding-3-small`。
- 评价指标：
  - **Success Rate**：能否产生有效且有事实支撑的回答；对不可答问题要求正确拒答。
  - **Win Rate**：用独立固定评测模型 Gemini 3.1-Pro-Preview 在所有回答中选择最优，若全部不正确则不给任何方法获胜。

### 3.3 主要实验结果
- 总体表现（GPT-5.2 骨干）：
  - SpecMind 整体 Win 率 **81.1%**，Success 率 **99.6%**；
  - Web-search RAG 整体 Win 7.9%，Success 50.5%；
  - SpectrumRAG 整体 Win 8.5%，Success 56.5%。
- Qwen3-8B 骨干下 SpecMind 整体 Win 66.2%，Success 89.8%，仍显著优于基线。
- 分类型看，SpecMind 在 License 和 Compound 问题上的增益最大，验证了 SQL 检索和多源协同推理的价值。
- 不可答问题（Negative）上所有方法成功率均接近/达到 100%，说明消歧和拒答能力主要依赖骨干 LLM 本身，而非检索框架。

### 3.4 消融实验
- 在 GPT-5.2 骨干下，将每个子代理单独替换为朴素 RAG（无重排模块）。
- 三个消融均导致性能下降：
  - 去掉 License Agent 的 SQL 检索后，License 问题 Win 率下降 **−87.8**，Success 率下降 **−82.8**，说明结构化的 SQL 检索非常关键；
  - 去掉 Proceeding Agent 的 GraphRAG 后，Proceeding 问题 Win 下降 **−27.3**，Success 下降 **−10.3**；
  - 去掉 Regulation Agent 的重排后，Regulation 问题仅小幅下降（Win −5.0，Success −6.4），说明文本检索本身较稳定。

### 3.5 案例分析与失败分析
- 给出一个代表性 compound 查询案例：12.7–13.25 GHz 频段卫星业务分配、Intelsat 是否为既有用户、各既有用户是否一致反对频谱共享。监督代理动态调用 Regulation → License → Proceeding 三个子代理逐步完成推理。
- 失败案例分析识别了三类剩余问题：
  1. 细粒度归因——图中实体与 filing 的共现未显式编码作者/被提及关系；
  2. 长尾实体稀疏证据——出现次数少的利益相关者难以检索到精确观点；
  3. 结构化查询歧义——某些 license ID 仅在服务子表内唯一，缺失服务类型可能导致聚合过宽。

## 6. 论文的主要结论与发现

- SpecMind 在多源、异构频谱数据上的 RAG 效果显著优于通用文本 RAG 与 SpectrumRAG，达到较高胜率。
- 不同数据结构需要匹配不同的检索机制：
  - **许可记录**应当用 SQL/关系数据库精确匹配，而非语义嵌入；
  - **多文档程序评论**适合图结构检索和多跳推理；
  - **法规文本**因其语义集中、文本规范，标准稠密检索+重排已经比较有效。
- 多智能体协调能够带来复合问题上的显著提升，但前提是各代理都具备独立可靠的能力。
- 进一步改进方向包括：更细粒度的归属元数据、对长尾实体的增强证据表达、以及针对模糊结构化查询的澄清机制。

## 7. 优点

- 首次（据作者所述）将多智能体混合 RAG 引入频谱智能，处理表格、图与文本异构数据。
- 数据库构建“模态感知”，不是把所有源统一做语义嵌入，而是针对数据特性设计向量库、图库和 SQL 库。
- 提出并公开专家设计的基准 SpecBench，覆盖真实 FCC 许可和程序数据，弥补了频谱 RAG 评测稀缺的问题。
- 可复用、可扩展的知识库设计有助于增量加入新记录，无需整体重建。
- 消融实验设计清晰，能量化每个子代理的贡献。
- 对失败案例进行了定性分析，有助于识别边界情况并指引未来改进。
- 开源了数据集、数据库与实现，支持复现和社区研究。

## 8. 不足与局限

- **实验覆盖范围有限**：仅使用单一 benchmark（SpecBench），未在另立的公开基准上做交叉验证，泛化性说服力有限。
- **评价偏差风险**：
  - Win Rate 依赖另一个专有 LLM（Gemini 3.1-Pro-Preview）作为裁判；若其偏好与某些回答风格相关，可能带来系统性偏差；
  - 骨干 LLM 仅两个（Qwen3-8B 和 GPT-5.2），未覆盖更多开源/闭源模型。
- **某些问题上区分度不足**：Unanswerable 类别所有方法都达到理想成功率，无法体现 SpecMind 对该类型的增量；
- **细粒度归因仍有限**：GraphRAG 图数据中实体与文件授权/被引用的关系未完全建模，影响需要精确归因的查询；
